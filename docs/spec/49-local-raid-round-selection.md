# 本地排刀候選與輪次選刀

domain/raid_planner.py 的 select_rounds 只完成主選刀，不能直接當作完整排刀最終結果發布。

## 版本與順位

- RaidProblem 固定成員、HP、BOSS 屬性、基準同步／傷害、歷史、原始指定、排名、input_versions、code_sha。
- 所有集合轉不可變 tuple；problem_id 包含完整輸入，RoundSelection.selection_id 另外包含候選、選擇與 algorithm_version。
- 排名直接由版本化模型輸入，不重新讀取輸出工作簿。
- 缺排名當最低順位；同排名依明確 element_tie_order，預設沿用核心 ELEMENTS 順序。這項確定性規則尚未對齊所有 GS localeCompare 環境，屬待完整遷移比較項目。
- 前三名同時含燃燒／鐵甲則把較差者移到第四；反向指定排除相關屬性的優先順位，未列入的 BOSS 屬性保留 fallback 群組。

## 來源池

- build_source_pool 先保存有效指定刀，再補 3 減歷史與指定的自動來源 token。
- token 有獨立 knife ID、group_rank、top_order；最終選刀可在允許群組中重新選目標，不把來源池當最終階段。
- 自動預排優先較前群組、較大估傷、較前王序；嚴格燃燒／鐵甲衝突失敗才放寬。
- 來源池可保存重複五王來源；實際選入重複刀必須在前段已清後鎖定 IV。

## 主選刀

- 前三輪由高同步到低同步，一人每輪最多選一刀；優先未使用的指定刀，維持原 slot 順序。
- 指定刀接受後仍完整模擬；其目標不改派，無法落地保留 stage=0 與 warning，留給後續指定保留流程。
- 自動主選只接受 group 0 來源與能補前段缺口的目標。尚未有燃燒／鐵甲時，先跨群組尋找其合法目標。
- 每個自動候選都完整模擬；不得增加缺口王數，同數時不得增加剩餘 HP，且不接受第三階段溢傷。
- 同時有選項時優先缺口、group、群組內順位、目標剩血、溢傷、估傷與王序。
- 之後由低同步到高同步補洞，允許較低群組及必要的元素衝突 fallback；整輪沒有進度即停止，循環有來源池大小上限。
- 非五王已無有限缺口時不再選入；只有全前段清空才允許重複 IV-5。
